# Дообучение Qwen на GSM8K

Два самостоятельных скрипта:

- `full_sft.py` — Full SFT, обновляются все веса модели.
- `lora.py` — LoRA, обновляются только веса адаптеров.

Каждый скрипт сам загружает данные и модель, подготавливает примеры, обучает модель и считает метрики. 

## 1. Где менять конфигурацию

В начале **каждого** Python-файла есть словарь `CONFIG`. Каждый параметр находится на отдельной строке. Отдельные файлы конфигурации не нужны.

Например, в `full_sft.py`:

```python
    "epochs": 3,
    "learning_rate": 2e-5,
    "batch_size": 1,
    "gradient_accumulation_steps": 16,
```

В `lora.py` дополнительно задаются:

```python
    "r": 16,
    "alpha": 32,
    "dropout": 0.05,
    "target_modules": ["q_proj", "v_proj"],
```


## 2. Запуск

Полное дообучение:

```bash
python full_sft.py
```

Один LoRA-эксперимент с настройками из `CONFIG`:

```bash
python lora.py
```

## 3. Данные и обучение

Используется [openai/gsm8k](https://huggingface.co/datasets/openai/gsm8k), конфигурация `main`: 7473 примера train и 1319 примеров test. Датасет подходит для исследования математических задач: содержит условия, пошаговые решения и числовые ответы после `####`. Несколько реальных примеров сохраняются при запуске в `dataset.json`.

Никакого дополнительного разделения нет: используются только готовые train и test. Обучение идет на train заданное число эпох. Сохраняется последняя эпоха; выбор лучшего чекпойнта по test не выполняется.

Вход оформляется через chat template модели. Loss считается по эталонному ответу ассистента; токены условия и padding маскируются значением `-100`. Слишком длинные примеры вызывают ошибку с предложением увеличить `max_length`, а не обрезаются молча.

Каждый запуск считает метрики на test до и после обучения. Test не участвует в обновлении весов. Если анализировать на нем все варианты LoRA, это исследовательское сравнение на одном тесте: подбор победителя по этим же результатам не дает независимой оценки обобщения.

## 4. Метрики

- **Accuracy** — доля задач с правильным итоговым числом, от 0 до 1. Генерация детерминированная, без sampling. Это основная метрика качества решения задач.
- **MAE** — средняя абсолютная разница между предсказанным и истинным числом. Показывает величину числовых ошибок, но зависит от масштаба ответов и единиц измерения задач.
- **Perplexity** — насколько хорошо модель предсказывает токены эталонных решений при teacher forcing. Считается только по ответам ассистента: сначала NLL усредняется по всем токенам, затем берется экспонента.

Число извлекается из ответа после `####`. Также принимается ответ, полностью состоящий из числа. Промежуточные числа из рассуждения не считаются итоговым ответом. Такой строгий протокол может засчитать правильное решение с другим оформлением как ошибку — это нужно учитывать при ручном просмотре.

Если число не распознано, ответ считается неправильным для accuracy. В JSON отдельно сохраняются:

- `parse_rate` — доля ответов, для которых удалось получить числовую ошибку;
- `invalid_answers` — количество остальных ответов;
- `mae_parsed` — MAE только по распознанным ответам;
- `mae_all` — MAE по всем примерам; `null`, если хотя бы один ответ не распознан.

Нельзя сравнивать `mae_parsed` без учета `parse_rate`: модель может пропускать сложные задачи и за счет этого получать маленькую условную ошибку.

Perplexity на GSM8K не измеряет разнообразие генераций и не проверяет сохранность общих знаний. Ее снижение означает лучшее предсказание эталонных решений при данном протоколе. Результаты также могут зависеть от присутствия публичного GSM8K в предобучении модели.

## 5. Где находятся результаты

Папки создаются автоматически рядом с `hw4_lora`:

```text
repository/
├── hw4_lora/
│   ├── full_sft.py
│   ├── lora.py
│   └── README.md
├── data/                          # кеш датасета
└── runs/
    ├── comparison.json            # все завершенные запуски
    └── дата_время_название/
        ├── config.json
        ├── dataset.json
        ├── environment.json
        ├── status.json
        ├── run.log
        ├── training.jsonl
        ├── metrics_base.json
        ├── metrics_tuned.json
        ├── predictions_base.json
        ├── predictions_tuned.json
        ├── manual_review.json
        ├── resources.json
        ├── results.json
        └── model/
```

`results.json` содержит конфигурацию, метрики исходной и обученной моделей, а также вычислительные затраты. `comparison.json` объединяет такие результаты в массив: один объект на запуск. При изменении данных или протокола в нем могут оказаться несопоставимые запуски — сравнивайте их конфигурации и `dataset.json`.

В `resources.json` записываются число обучаемых параметров, время `trainer.train()` и пики выделенной/зарезервированной PyTorch GPU-памяти за обучение. Пики не включают отдельную оценку до/после обучения. Это учет памяти PyTorch, а не всей памяти процесса по `nvidia-smi`. Для сравнения времени и памяти используйте одну и ту же GPU.

В Full SFT папка `model` содержит полную модель; в LoRA — адаптер и токенизатор. Исходная модель для адаптера остается необходимой.

## 7. Ручная оценка и выводы

Откройте `manual_review.json` после Full SFT и после базовой LoRA. В файлах используются одинаковые первые 10 примеров test: можно сопоставить исходную модель, Full SFT и LoRA по `test_id`. Посмотрите правильность рассуждений, вычисления и оформление итогового ответа. Впишите наблюдения в `human_comment`. Автоматическая проверка итогового числа сама по себе не является ручной оценкой.

Для отчета перенесите из JSON следующие столбцы в таблицу:

| Модель / конфигурация | Accuracy | MAE parsed | Parse rate | Perplexity | Обучаемые параметры | Время, сек | Пик allocated, GiB |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Исходная Qwen | | | | | — | — | — |
| Full SFT | | | | | | | |
| Базовая LoRA | | | | | | | |
| Остальные LoRA-эксперименты | | | | | | | |

Выводы заполняются после реальных запусков. Сравните качество Full SFT и LoRA с затратами; для каждого LoRA-параметра сопоставьте вариант с базовой конфигурацией. При изменении `r` с фиксированным `alpha` меняется также масштаб `alpha/r`, поэтому наблюдаемый эффект нельзя объяснять только емкостью адаптера. При расширении `target_modules` одновременно растет число обучаемых параметров.

Один seed дает предварительные результаты. Небольшие различия качества без повторных запусков могут быть случайными.
